# Our own Qt Quick Controls style, in a separate design module

The look of the app lives in `src/design/`, its own QML module and CMake target (`JunctionDesign`) holding the tokens, a custom Qt Quick Controls style and a few shared components; `main.cpp` selects that style instead of Fusion, which stays only as the fallback for controls we have not styled. We chose a real controls style over wrapper components (`AppButton` on top of Fusion) because with a style the consistent look is the default: plain `Button {}` comes out right and nobody can pick the "wrong" button, whereas wrappers rely on everyone remembering to use them, which is how the drift we had began. We chose a separate module over a folder inside the app module because the build then enforces the boundary: design code cannot reach `Editor`, the Library or Canvas logic, and the `junction-gallery` app, built against `JunctionDesign` alone, stops compiling if it ever does. The cost is writing the templates for the ~11 controls the app uses, and moving the tokens out of the app module (a style cannot import the module that uses it).
